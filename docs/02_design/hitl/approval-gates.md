# Human-in-the-Loop Approval Gates

> **Owner**: Human (Product Owner)
> **Last Updated**: 2026-01-21
> **Status**: Draft

## 1. Overview

このドキュメントは、AIエージェントの自律実行を一時停止し、
人間による確認・承認を必要とするポイント（ゲート）を定義する。

## 2. Gate Summary

| Gate ID | Trigger Point | Required Action | Timeout | Critical |
|---------|---------------|-----------------|---------|----------|
| HITL-001 | 現状分析完了時 | 分析結果の確認 | 72時間 | No |
| HITL-002 | 求める人材像生成後 | 承認/改善リクエスト | 72時間 | Yes |
| HITL-003 | 等級制度案生成後 | 承認/改善リクエスト | 72時間 | Yes |
| HITL-004 | 評価制度案生成後 | 承認/改善リクエスト | 72時間 | Yes |
| HITL-005 | 報酬制度案生成後 | 承認/改善リクエスト | 72時間 | Yes |
| ~~HITL-006~~ | ~~コンプライアンスチェック後~~ | ~~リスク確認~~ | - | - |
| HITL-007 | ドキュメント生成後 | 最終承認 | 48時間 | Yes |

> **Note (MVP)**: HITL-006（コンプライアンスチェック）はMVPでは省略。PRODUCT_BRIEFにて「法規制: 特に参照する必要なし」と定義されているため。Phase 2以降で必要に応じて追加。

## 3. Dependency Flow

```
HITL-001（分析確認）
    │
    ↓ 承認後
HITL-002（人材像承認）
    │
    ↓ 承認後
HITL-003（等級制度承認）
    │
    ↓ 承認後
HITL-004（評価制度承認）
    │
    ↓ 承認後
HITL-005（報酬制度承認）
    │
    ↓ 承認後
HITL-007（最終承認）  ← MVP: HITL-006スキップ
    │
    ↓ 承認後
[完了]
```

**重要**: 各ゲートは順序依存。前のゲートが承認されるまで次のゲートには進めない。

## 4. Gate Details

### 4.1 HITL-001: 現状分析確認

| Item | Value |
|------|-------|
| Gate ID | HITL-001 |
| Trigger | PolicyAnalystエージェントによる分析完了 |
| Timeout | 72時間 |
| Critical | No（タイムアウト時は自動継続可） |

#### 表示内容

| Content | Description |
|---------|-------------|
| 業界ベンチマーク | 同業他社との比較データ |
| 検出された課題 | AIが検出した課題リスト（優先度付き） |
| 改善の方向性 | 推奨されるアプローチ |

#### ユーザーアクション

| Action | Result |
|--------|--------|
| 確認完了 | HITL-002（人材像生成）へ進む |
| 修正 | 分析内容を編集、再保存 |
| 再分析 | 追加情報を元に再分析を実行 |

#### 判断基準（人間が確認すべきこと）

- [ ] 分析が自社の実態と合致しているか
- [ ] 見落としている課題がないか
- [ ] 業界特性が正しく反映されているか

#### 改善リクエスト理由の例

- 「現行制度の理解が誤っている」
- 「業界特性が反映されていない」
- 「追加の情報を考慮してほしい」

### 4.2 HITL-002: 求める人材像承認

| Item | Value |
|------|-------|
| Gate ID | HITL-002 |
| Trigger | 人材像の自動生成完了 |
| Timeout | 72時間 |
| Critical | Yes（タイムアウト時は自動継続不可） |

#### 表示内容

| Content | Description |
|---------|-------------|
| ビジョン | 目指す人材像（1-2文） |
| 価値観 | 大切にする価値観リスト（3-5個） |
| 行動特性 | 期待する行動リスト（3-7個） |

#### ユーザーアクション

| Action | Result |
|--------|--------|
| 承認 | HITL-003（等級制度生成）へ進む |
| 編集 | 各項目を編集、再保存 |
| 改善リクエスト | フィードバック入力後、再生成 |

#### 判断基準（人間が確認すべきこと）

- [ ] 経営理念・ビジョンと整合しているか
- [ ] 現実的に達成可能な人材像か
- [ ] 従業員に伝わる表現になっているか

#### 改善リクエスト理由の例

- 「経営理念との整合性が低い」
- 「表現が抽象的すぎる」

### 4.3 HITL-003: 等級制度承認

| Item | Value |
|------|-------|
| Gate ID | HITL-003 |
| Trigger | 等級制度案の自動生成完了 |
| Timeout | 72時間 |
| Critical | Yes |

#### 表示内容

| Content | Description |
|---------|-------------|
| 等級階層 | G1〜GN の階層定義 |
| コンピテンシー | 3つのコンピテンシー |
| コンピテンシー要素 | 各コンピテンシーの2要素（計6要素） |
| 卒業要件 | 等級×要素のマトリクス |
| 給与レンジ | 各等級の給与範囲（オプション） |

#### ユーザーアクション

| Action | Result |
|--------|--------|
| 承認 | HITL-004（評価制度生成）へ進む |
| 詳細編集 | 各要素を個別に編集 |
| 改善リクエスト | フィードバック入力後、再生成 |

#### 判断基準（人間が確認すべきこと）

- [ ] 等級数は適切か（多すぎ/少なすぎないか）
- [ ] コンピテンシーは自社の価値観と整合しているか
- [ ] 卒業要件は現実的かつ測定可能か
- [ ] 運用できるシンプルさか

#### 改善リクエスト理由の例

- 「等級数が多すぎて運用が難しい」
- 「コンピテンシーが自社の価値観と合わない」
- 「卒業要件が抽象的で評価しにくい」

### 4.4 HITL-004: 評価制度承認

| Item | Value |
|------|-------|
| Gate ID | HITL-004 |
| Trigger | 評価制度案の自動生成完了 |
| Timeout | 72時間 |
| Critical | Yes |

#### 表示内容

| Content | Description |
|---------|-------------|
| 評価種別 | コンピテンシー評価（MVP: 固定） |
| 評価期間 | 年次/半期/四半期 |
| コンピテンシー評価 | 6要素 × 5段階（1-5）、昇格閾値: 全て4以上 |
| 成果評価 | ⚪︎/△/× の3段階、×で昇格不可 |
| 振る舞い評価 | ⚪︎/△/× の3段階、×で昇格不可 |
| 昇格ロジック | 成果≠× AND 振る舞い≠× AND 全コンピテンシー≥4 |

#### ユーザーアクション

| Action | Result |
|--------|--------|
| 承認 | HITL-005（報酬制度生成）へ進む |
| 編集 | 各要素を編集 |
| 改善リクエスト | フィードバック入力後、再生成 |

#### 判断基準（人間が確認すべきこと）

- [ ] 評価頻度は適切か
- [ ] コンピテンシー評価の6要素は等級制度と整合しているか
- [ ] 成果評価・振る舞い評価の基準は明確か
- [ ] 昇格ロジックは公平で運用可能か
- [ ] 運用負荷は許容範囲か

## 5. Timeout Handling

### 5.1 Timeout Rules

| Gate Type | Timeout Action |
|-----------|----------------|
| Non-Critical (HITL-001) | 自動継続、リマインダー送信 |
| Critical (HITL-002〜007) | 一時停止、エスカレーション |

### 5.2 Notification Schedule

| Timing | Action |
|--------|--------|
| ゲート開始時 | 通知送信 |
| 残り24時間 | リマインダー送信 |
| 残り4時間 | 緊急リマインダー送信 |
| タイムアウト | ステータス更新、エスカレーション |


## 6. Rejection Handling

### 6.1 Rejection Flow

```
[改善リクエスト] → [フィードバック入力] → [AI再生成] → [レビュー画面]
```

### 6.2 Feedback Input

| Field | Required | Description |
|-------|----------|-------------|
| 改善リクエスト理由 | Yes | 選択式（複数選択可） |
| 詳細説明 | No | 自由記述 |
| 参考資料 | No | ファイルアップロード |

### 6.3 Rejection Limits

| Rule | Value |
|------|-------|
| 同一ゲートの最大改善リクエスト回数 | 5回 |
| 5回超過時 | 人間によるマニュアル編集モードへ |
