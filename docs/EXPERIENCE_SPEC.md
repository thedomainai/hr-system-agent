## 1. Design Principles

<!--
このプロダクトのUX設計における原則
全ての画面設計・インタラクション設計はこれに従う
-->

### 1.1 Core Principles

| # | Principle | Description | Example |
|---|-----------|-------------|---------|
| P1 | **Passivity for Users** | ユーザーは受動的でよい。プロジェクト管理と提案はAIが主導し、ユーザーは「判断」に集中する。 | 「次はどうしますか？」ではなく「次はこれを確認してください」と提示する。 |
| P2 | **Uncompromising Quality** | 曖昧さを徹底的に排除する。論理と表現にこだわり、プロフェッショナル品質を担保する。 | 「いい感じの制度」ではなく、具体的な行動指標まで言語化された制度を出す。 |
| P3 | **Transparency** | ブラックボックスにしない。AIの思考プロセスや提案の背景（Why）を可視化する。 | 「なぜこのコンピテンシーを選んだのか」の理由を併記する。 |
| P4 | **Contextual Efficiency** | 必要な時に必要な情報だけを出す。専門用語は避け、経営者の言葉で語る。 | 複雑な法律用語ではなく、「要するにこういうことです」と解説する。 |

### 1.2 Anti-Patterns

<!--
避けるべきパターン
-->

| # | Anti-Pattern | Why Avoid |
|---|--------------|-----------|
| A1 | **Open-ended Questions** | ユーザーに「どうしたいですか？」と丸投げすると、思考コストがかかり、品質がブレる。常に「案」を出し、Yes/No/Modifyで答えさせる。 |
| A2 | **Jargon Overload** | 人事/労務の専門用語を羅列すると、ユーザーが委縮する。わかりやすい言葉への翻訳を徹底する。 |
| A3 | **Dead Ends** | 「エラーです」で止まるのはNG。「こう修正すれば直ります」という解決策を常に提示する。 |

## 3. Screen Specifications

### 3.1 Screen: 企業登録

| Item | Value |
|------|-------|
| Screen ID | SCR-001 |
| Purpose | 制度設計に必要な企業情報を収集する |
| Entry Point | ダッシュボード「新規作成」ボタン |
| Exit Point | 「登録完了」→ 現状分析へ |

#### Input Elements

| Field | Type | Required | Validation | Help Text |
|-------|------|----------|------------|-----------|
| 企業名 | text | Yes | 1-100文字 | 正式名称を入力してください |
| 従業員数 | number | Yes | 1以上 | パート・アルバイトを含む総数 |
| 現行制度 | multi-select | No | - | 既にある制度があれば選択 |
| 経営理念 | textarea | No | 500文字以内 | ミッション・ビジョン・バリューなど |
| 課題感 | textarea | No | 1000文字以内 | 現在困っていること、解決したいこと |

#### User Actions

| Action | Trigger | Result |
|--------|---------|--------|
| 登録 | 必須項目入力後「登録」ボタン | 企業作成、分析開始 |
| キャンセル | 「キャンセル」ボタン | ダッシュボードへ戻る |

#### Emotional Goal

> 「これなら簡単に始められそうだ」「面倒な入力作業は少なそうだ」と感じる

### 3.2 Screen: 現状分析レビュー (HITL-001)

| Item | Value |
|------|-------|
| Screen ID | SCR-002 |
| Purpose | AIによる分析結果を確認・承認する |
| HITL Gate | HITL-001 |
| Timeout | 72時間 |

#### Display Elements

| Element | Content | Note |
|---------|---------|------|
| 業界ベンチマーク | 同業他社との比較データ | 従業員規模・業界平均との乖離をグラフ表示 |
| 検出された課題 | AIが検出した課題リスト | 優先度（高・中・低）と理由を表示 |
| 改善の方向性 | 推奨されるアプローチ | 「〇〇型等級制度の導入」など具体的な方向性 |

#### User Actions

| Action | Trigger | Result |
|--------|---------|--------|
| 確認完了 | 「確認完了」ボタン | 次ステップへ（人材像生成） |
| 修正 | 「修正」ボタン | 課題や方向性の手動編集モードへ |
| 改善リクエスト | 「再分析」ボタン | 分析条件を変更して再実行 |

#### Emotional Goal

> 「自社の課題が的確に言語化されている」「プロに見てもらっているようだ」と感じる

### 3.3 Screen: 求める人材像レビュー (HITL-002)

| Item | Value |
|------|-------|
| Screen ID | SCR-003 |
| Purpose | 生成された人材像を確認・承認する |
| HITL Gate | HITL-002 |
| Timeout | 72時間 |

#### Display Elements

| Element | Content | Note |
|---------|---------|------|
| ビジョン | 目指す人材像 | 1-2文のキャッチフレーズ |
| 価値観 | 大切にする価値観リスト | 3-5個のキーワードと定義 |

#### User Actions

| Action | Trigger | Result |
|--------|---------|--------|
| 承認 | 「承認」ボタン | 等級制度生成へ |
| 編集 | 各項目の「編集」ボタン | インライン編集 |
| 改善リクエスト | 「再生成」ボタン | 指示（もっとアグレッシブになど）を与えて再生成 |

#### Emotional Goal

> 「これが我が社の理想の人材だ」「この言葉なら社員に響きそうだ」と確信できる

### 3.4 Screen: 等級制度レビュー (HITL-003)

| Item | Value |

| Screen ID | SCR-004 |

### 3.6 Screen: 報酬制度レビュー (HITL-005)

| Item | Value |
|------|-------|
| Screen ID | SCR-006 |
| Purpose | 生成された報酬制度を確認・承認する |
| HITL Gate | HITL-005 |
| Timeout | 72時間 |

#### Display Elements

| Element | Content | Note |
|---------|---------|------|
| 給与テーブル | 等級ごとの給与レンジ (Min/Mid/Max) | グラフ表示（バンド幅を表示） |

| Action | Trigger | Result |
|--------|---------|--------|

| パラメータ調整 | レンジ・係数のスライダー操作 | リアルタイムでシミュレーション反映 |
| 編集 | 手当等の追加・削除 | 編集画面へ |

#### Emotional Goal

> 「市場競争力がありつつ、経営としても持続可能だ」と安心する

### 3.7 Screen: 最終確認・ドキュメント生成 (HITL-006)

| Item | Value |
|------|-------|
| Screen ID | SCR-008 |
| Purpose | 全制度を最終確認し、ドキュメントを生成する |
| HITL Gate | HITL-006 |
| Timeout | 48時間 |

#### Display Elements

| Element | Content | Note |
|---------|---------|------|
| 全体サマリ | 策定した全制度の要約 | 一覧表示 |
| 法令チェック結果 | コンプライアンスチェックレポート | OK/NG/Warning を表示 |
| 成果物リスト | 生成されるドキュメント一覧 | 規程、マニュアル、概要資料など |
| ダウンロード | 一括ダウンロードボタン | PDF/Word形式 |

#### User Actions

| Action | Trigger | Result |
|--------|---------|--------|
| 最終承認 | 「プロジェクト完了」ボタン | ステータスを完了にし、納品物を確定 |
| 修正に戻る | 各セクションへのリンク | 該当ステップへ戻って修正 |

#### Emotional Goal

> 「これで制度設計が完了した」「プロに頼んだような高品質な成果物が手に入った」と達成感を感じる

## 4. Error Flows

### 4.1 改善リクエストフロー

```
[レビュー画面] ──[改善リクエスト]──→ [フィードバック入力]
                                    │
                                    ↓
                              [AI再生成]
                                    │
                                    ↓
                              [レビュー画面]
```

#### フィードバック入力画面

| Element | Content |
|---------|---------|
| 改善リクエスト理由 | 選択式（例：難易度が高すぎる、表現が堅苦しい、等） |
| 詳細フィードバック | 自由記述（具体的な修正指示） |
| 参考情報 | ファイルアップロード（既存資料などを参考にしてほしい場合） |

### 4.2 タイムアウトフロー

```
[レビュー画面] ──[72時間経過]──→ [タイムアウト通知]
                                      │
                                      ↓
                              [再開 or キャンセル]
```

## 6. Accessibility Requirements

<!--
アクセシビリティ要件
-->

| Requirement | Target | Note |
|-------------|--------|------|
| WCAG Level | WCAG 2.1 Level AA | 可能な限り準拠する |
| キーボード操作 | 全操作可能 | マウスなしでTabキー等で操作できること |
| コントラスト比 | 4.5:1 以上 | テキストと背景のコントラストを確保 |
| スクリーンリーダー | 対応 | 見出し構造、Alt属性、ARIAラベルを適切に設定 |
